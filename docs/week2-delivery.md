# 第二周交付与验收记录

2026-11-17，按 [三周开发方案](development-plan.md) 的第二周范围完成。本地中等规模练习：单个 Agent、三个只读工具、模拟数据、显式确认创建工单。没有接入真实企业系统、SSO、权限开通、审批平台或多 Agent。

## 逐项验收

| 第二周要求 | 当前实现与证据 |
|---|---|
| LangGraph 分诊、决策、执行、生成、校验、保存 | `prepare → triage → plan ⇄ tools → final → validate → persist`。分诊输出类别、意图、优先级建议、缺失信息；信息不足走 `needs_info → validate → persist`，不调用工具。`app/agent.py`、`app/schemas.py::Triage`，自动化分诊/路由测试与真实 needs_info 请求通过。 |
| 三种只读工具与上限 | `search_knowledge`、`get_service_status`、`get_ticket_status`。模型每次只能提出一个工具，三次尝试硬上限，非法调用/参数也扣次数；多工具批次拒绝执行。状态数据含正常与故障快照。`app/tools.py` 与工具额度、参数、错误恢复测试；真实手册、正常服务、降级邮箱及工单查询通过。 |
| 异步 SQLite Checkpointer、多轮和重启历史 | `AsyncSqliteSaver + aiosqlite`，线程编号为会话编号。模型读取最近8条消息，状态事实本轮重新查询。自动化真实SQLite重开测试通过；真实进程重启前后消息与待确认草稿完全一致，并可重启后确认。见 `week2-restart.json`。 |
| 草稿、确认、取消、工单查询、审计 | `finish_turn` 在同一事务保存回答、草稿和审计；确认固定读取已存草稿，工单/草稿状态/审计一起提交。确认body只允许 `{}`，客户端不能替换字段。未确认无工单，取消不能确认，重复确认仅一个工单；并发与SQL故障注入测试通过。 |
| Streamlit 工单列表、确认按钮和工具轨迹 | 后端历史切换、刷新/URL恢复、分类与追问提示、引用原文、工具轨迹、草稿预览、确认/取消、工单列表。3项可重复AppTest通过；实际浏览器点击确认成功，见截图。 |
| 单进程、同会话每次一个请求 | 启动脚本固定 `--workers 1`；会话忙返回409，消息 `request_id` 完成后结果重放。相同编号换问题拒绝；中断请求返回明确冲突，重新提问使用新编号。并发、重放和HTTP边界测试通过。 |

## 演示与复现

按 [README](../README.md) 启动API和页面，打开 <http://127.0.0.1:8501>：

1. 输入“帮我处理一下”，查看缺失信息提示；再补充“VPN-403 设备未授权”。
2. 追问“那这个服务在模拟系统中正常吗？”，查看服务工具轨迹。查询“现在模拟邮箱服务有故障吗？”可显示降级快照。
3. 查询 `IT-1001`，再查不可见的 `IT-2001`；后者和不存在工单返回相同不可查询结果。
4. 输入“VPN-403 排查后仍失败，请准备人工工单草稿”，核对草稿后取消或点击确认。确认时不调用模型，重复确认返回同一编号。
5. 刷新/切换会话，或重启API再恢复历史。修改问题需新请求ID；进程中断的旧请求不会自动续跑。

自动化检查：

```powershell

.\.venv\Scripts\python.exe -m pip check

```

## 实现限制与下一周边界

同一会话只支持一个处理中请求，单进程内存忙状态不能用于多个worker；模型上下文截断为最近8条消息。Checkpoint保留状态用于诊断，业务库是已完成回复/草稿/工单的事实来源；不承诺自动恢复任意中断节点。两库无跨库事务，业务提交后Checkpoint失败时优先返回已提交业务结果。

整轮90秒、工具10秒、上游请求20秒；上游SDK最多一次瞬时重试。分诊格式和最终结构化结果各最多修复一次。达到工具次数上限仍可返回拒答或草稿。所有者隔离是固定演示身份的数据过滤，不是登录/RBAC或真实企业审批。

本机业务数据库与Checkpoint保存明文消息、答案和工具结果；`agent.log`仅保存节点、运行编号、状态、耗时、累计用量与异常类型，轮转约3MB。请仅使用模拟数据。未实现语义引用评审、自动内容脱敏、数据保留期限或多机安全能力。

第二周已经具备四条可演示业务链路。第三周仍需按原方案完成80条人工复核用例（20开发、60冻结验收）、检索方案对比、人工证据支持率/分类质量报告与简历材料；本次没有用开发结果替代这些后续工作。
