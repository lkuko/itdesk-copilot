# 第三周实测报告

实测日期：2026-11-17。第三周完成80条案例执行、配对检索实验、逐条来源复核、故障测试和复现检查。结果适用于24篇虚构手册、固定模拟状态和本地工单，不能推断真实企业业务收益。

用户明确选择了**先由AI对照原文逐条复核**。本报告将其记为AI辅助评分；没有真人评审，原方案“人工证据支持率≥85%”仍为**未验证**。测试通过、引用存在、来源支持和业务任务完成分别统计。

## 3. 检索对照：没有测出额外收益

验收仅28条带来源文档金标的请求参与检索对比（24知识 + 2知识多轮 + 2知识安全题）。多轮查询采用历史用户问题与本轮问题拼接。两策略使用**同一查询、同一个Embedding向量、同一索引、阈值和Top5**，交替执行顺序，仅切换完整错误码优先及同文档邻片段扩展，测量的是这套组合策略，不是单独错误码规则的因果效应。

| 策略 | Recall@5 | Hit@5 | MRR@5 | 本地检索P50 |
|---|---:|---:|---:|---:|
| 纯向量 | 1.000（28/28） | 1.000 | 1.000 | 30.79毫秒 |
| 错误码与向量组合 | 1.000（28/28） | 1.000 | 1.000 | 30.35毫秒 |

15条查询含完整错误码、13条不含；两个子集两策略也均召回金标文档。开发集10条配对题同样均为1.000。这里是**文档级**Recall：同文档任一片段出现即命中，不代表验证、人工升级等关键段落全部返回，也不衡量答案完整性。MRR按原始片段排名中首次相关文档计算。

验收收益0条、退化0条、持平28条。小知识库与单来源题存在天花板效应，不能写“混合检索显著提升准确率”。毫秒差异缺少重复试验和负载控制，不能当性能提升证据；在线Embedding时延另存原始结果，不包含在这里的本地检索时间中。

受控单元测试证明精确码在向量结果被阈值挡住时能够找回文档，但这是构造条件下的能力检查，不能替代本次真实对比的零增益结论。Agent累计证据中命中28/28也单独统计：它可发起最多3次查询，不能将累计命中率冒充单次Top5。

## 4. 答案质量：AI辅助来源复核

逐题检查当前回答、草稿、用户明确陈述、实际工具结果及原始手册，而非关键词自动评分。`supported`要求所有实质事实有来源，存在一项未支持事实就记false；`task_correct`另检查意图和下一步是否完成；`unsafe_claim`检查危险操作、凭证暴露或虚构执行等。复核表包含理由和来源位置。

| 指标 | 开发 | 验收 |
|---|---:|---:|
| 已完成逐题复核 | 20/20 | 50/50 |
| 实质回答/草稿证据支持 | **14/15（93.33%）** | **37/38（97.37%）** |
| 所有案例任务正确 | **17/20（85.00%）** | **49/50（98.00%）** |
| 观察到不安全断言 | 0/20 | 0/50 |
| 真人证据支持率 | 未验证 | 未验证 |

支持率分母仅包含`answered`与`pending_confirmation`，开发另外5条、验收另外12条拒答或澄清不计入支持率，仍参与任务正确性复核。全50条中49条支持这一计数不能改称49/50“知识答案支持率”。AI评分可能有偏差，知识题复核者也参与了金标编写，不是独立或盲法真人评审；0条不安全断言也不证明模型不会被注入。

用户选择的评分方式已完成，原计划的人评目标不据此判定达标。待未来有人评时，应另存评审者、日期、逐题判定和分歧处理，不能覆写AI评分记录。
