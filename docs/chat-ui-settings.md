# 聊天界面与显示设置交付说明

日期：2026-11-18。本轮继续优化 ITDesk Copilot 的聊天界面，并增加独立的显示设置页。沿用 Streamlit、FastAPI 与原有单 Agent，保持本机中等规模演示；知识问答、会话管理、来源追溯、草稿修改和按钮确认流程继续保留。

本文描述[前一轮前端优化](frontend-delivery.md)之后的页面变化。第三、四周的模型评测、题目、原始响应和证据仍是各自版本快照，不把此次界面调整当作模型质量提升。

## 1. 参考范围与页面结构

本轮实际浏览了 ChatGPT 公共首页与豆包公共聊天页，参考其常见的聊天布局：紧凑侧栏、简洁顶栏、围绕输入框的欢迎区、较轻的消息样式，以及独立设置入口。DeepSeek、Claude 仅到登录或验证页面，未继续检查登录后的聊天工作区。因此这里只说明已观察的公开页面，不宣称比较了五家产品的完整功能或设置。

页面继续使用自有 ITDesk 名称、服务台语境与品牌标识，没有照搬其他产品的账号体系、品牌资产、模型选择器或能力承诺。

| 区域 | 当前组织方式 | 保留的业务边界 |
|---|---|---|
| 侧栏 | 新会话、问答助手、历史工单、最近会话列表；知识与服务可折叠；底部为设置入口。 | 会话切换、重命名、显式确认删除仍使用持久化记录；删除对话不删除已建工单。 |
| 主区顶栏 | ITDesk 名称、IT 服务助手说明与本地服务状态。 | 本地配置和索引就绪，不等于远端模型实时可用。 |
| 空会话 | 简短欢迎语、居中输入框、可选推荐问题。 | 示例只预填，确认发送后才进入原有请求链。 |
| 已有对话 | 用户与助手分区、引用原文、可折叠只读工具记录；草稿继续单独核对。 | 来源和工具记录不会因默认收起或隐藏运行指标而删除。 |
| 设置 | 通用、聊天显示、关于与状态三个页签，统一保存。 | 只改变显示；不修改模型参数、工具上限、工单写入权限或业务数据。 |

当前样式使用约 260px 侧栏和 900px 主区最大宽度，窄屏通过框架原生入口折叠侧栏。浅色、深色和跟随系统共享同一组语义令牌；保留焦点样式和减少动态效果规则。具体布局应以本轮截图和浏览器核验为准，不沿用前一轮尺寸作为本轮实测。

## 2. 八项显示设置

在侧栏选择“设置”。表单分为“通用”“聊天显示”“关于与状态”，调整选项后点击“保存设置”才写入并应用。切换页签本身不保存；未保存的选项不会影响对话。保存失败时提示检查本机目录权限，当前已应用设置保持不变。

| 设置 | 存储字段与可选值 | 默认值与实际作用 |
|---|---|---|
| 界面主题 | `theme`：`system` / `light` / `dark` | 跟随系统；控制页面配色，通过系统媒体查询适配深色。 |
| 正文字号 | `font_size`：`small` / `standard` / `large` | 标准；通过样式变量调整主要消息文字与输入文字，不等于缩放整页。 |
| 阅读密度 | `density`：`comfortable` / `compact` | 舒适；调整消息间距，不缩小操作按钮的点击区域。 |
| 在新会话显示推荐问题 | `show_examples`：布尔值 | 开启；只控制空会话的推荐问题区，不影响手动提问。 |
| 显示消息时间 | `show_timestamps`：布尔值 | 关闭；有保存时间的消息才展示时间，不补造历史时间。 |
| 显示耗时、Token 与费用 | `show_metrics`：布尔值 | 关闭；开启后在运行记录中显示已有指标；费用未知仍显示未知，不写成零。工具步骤与错误仍可查看。 |
| 展开引用原文 | `expand_sources`：布尔值 | 关闭；控制引用卡片的默认展开状态，原文仍可逐条展开。 |
| 展开只读工具与运行记录 | `expand_tools`：布尔值 | 关闭；控制运行记录的默认展开状态，不改变实际调用次数。 |

“关于与状态”显示本机模拟说明、单 Agent 与工具边界、知识库数量、索引更新时间，以及服务返回的模型名称。它不提供 API Key、服务地址或其他凭证编辑入口。健康检查不发送模型请求，设置页也不做新的远端能力测试。

“恢复默认设置”单独执行默认偏好保存并立即应用，成功后给出提示；它不会清空会话、草稿、工单或请求记录。若恢复写入失败，当前偏好保持不变。

## 3. 本地持久化与多浏览器限制

默认文件为项目下的 `data/ui-preferences.json`。只保存上表八个显示字段，不保存聊天内容、模型密钥、服务地址或身份信息。UI 进程可用 `ITDESK_UI_PREFERENCES_PATH` 覆盖路径；该变量属于进程环境，不由页面编辑，也不会自动从项目 `.env` 加载。

```powershell
# 可选：为此 UI 进程使用另一份本地显示偏好
$env:ITDESK_UI_PREFERENCES_PATH = '.\data\ui-preferences.json'
powershell -ExecutionPolicy Bypass -File .\scripts\start-ui.ps1
```

偏好模块不依赖 Streamlit。读取缺失、不可读、损坏 JSON 或非对象内容时返回默认值；对象中的未知字段忽略、非法值按字段回默认，读取不会自动覆盖原文件。保存时严格校验字段和值，布尔开关不接受字符串或 `0/1`；未知字段与非法值抛出 `PreferencesError`，不写磁盘。

保存先在目标目录创建临时文件，写入、刷新并同步后调用 `os.replace` 替换目标；替换失败保留旧文件并尽力清理临时文件，I/O 错误交给页面提示。此机制避免半份 JSON，不构成数据库事务或多用户配置服务。

这是**本机单用户共享偏好**。同一 UI 服务使用同一文件的浏览器共享最后保存值，不是按账号或浏览器隔离。一个页面初次建立 Streamlit 会话时读取文件，之后使用该会话已应用值；其他已打开的页面不会接收实时推送，应重新打开或重建页面会话后读取新值。并发保存采用最后成功写入者覆盖，没有跨浏览器合并或冲突提示。

## 4. 源码目录与符号链路

```text
ui/
  app.py                    Streamlit 薄入口
  workbench.py              页面状态、聊天、设置表单与保存反馈
  preferences.py            固定偏好 schema、读取、校验、原子保存与恢复默认
  styles.py                 品牌与明暗令牌、字号/密度变量、响应式样式
  enhancements.js           原生输入计数与中文可访问性标签
tests/
  test_ui_preferences.py    临时真实文件的读写、校验与故障回滚
  test_week2_ui.py           聊天流程、设置应用、重开恢复和数据保留的 AppTest
```

主要调用链：

1. `ui/app.py` 导入并调用 `workbench.main`。
2. `initialize_state → load_preferences` 仅在当前页面会话尚无已应用偏好时读本地文件；`preference` 始终读取已应用值，不从未保存表单取值。
3. `main → render_styles(theme, font_size, density)` 生成样式；聊天分支分别在 `render_examples`、消息时间、`render_sources`、`render_diagnostics` 消费显示开关。
4. `render_sidebar → set_view('settings') → render_settings` 打开设置页。`st.form` 收集 `pref_*` 临时字段，点击保存后调用 `ui/preferences.py` 的 `save_preferences`。
5. `save_preferences → 固定 schema 校验 → 同目录临时文件 → flush/fsync → os.replace`；成功后页面更新已应用偏好并重绘，失败只提示，不提前应用表单值。
6. `restore_default_preferences → reset_preferences → save_preferences(DEFAULT_PREFERENCES)`；成功后同步已应用值和表单默认值，不调用会话或工单删除接口。

样式入口是 `ui/styles.py` 的 `render_styles`，输入增强在 `ui/enhancements.js`。设置模块没有新 API、数据库迁移或 Provider 调用。原请求仍经 `submit_pending → ask_question → POST messages` 进入现有 Agent；工单确认仍通过固定后端接口读取持久化草稿。

## 5. 验证与证据入口

本轮全量自动化测试 **209 项通过**；设置持久化与 UI 专项复测 **58 项通过**（其中偏好模块 34 项、UI 24 项，是全量测试的子集，不重复计数）。Ruff 与依赖完整性检查通过。实际执行命令、测试耗时和检查结论见[本轮验收摘要](evidence/chat-settings-checks.json)及[JUnit](evidence/chat-settings-tests.xml)；当前源码摘要与符号位置分别见[SHA-256](evidence/chat-settings-source-sha256.json)、[源码索引](evidence/chat-settings-source-map.json)。

真实浏览器检查覆盖 1280×720 桌面和 390×844 手机视口：保存前不应用、保存后刷新恢复、字号与消息间距、推荐问题与消息时间、运行指标、引用/工具展开、设置页签和侧栏收展。实屏发现并修复暗色展开标题、提示卡片与引用原文的浅色底问题，以及桌面折叠侧栏占位和手机历史会话管理按钮换行问题。手机文档宽度为 390px，没有横向溢出；临时视口覆盖已重置。

验收结束通过页面恢复默认偏好。最终验收前后对原有业务表行内容进行只读摘要比对；原会话、消息、草稿、工单和审计记录未被改写。点击“新会话”验证导航时新增一条空的本地演示会话，未发送问题、未生成草稿或工单；该增量在验收摘要单独记录。未调用远端模型。

## 6. 演示顺序与限制

1. 展示新的聊天首屏、侧栏与服务状态；点击推荐问题，说明只预填、不自动发送。
2. 进入“设置”，调整主题、字号和密度；保存前返回对话，观察仍使用原已应用值，再回设置重新选择并保存。
3. 在“聊天显示”选择时间、指标和引用/工具默认展开；保存后恢复已有演示会话，观察各设置对应变化。
4. 重新打开页面，确认读取本地偏好；执行“恢复默认设置”，确认消息、草稿和工单仍存在。
5. 展示“关于与状态”，说明模拟系统、本机存储、健康检查与远端模型能力的区别。

演示已有记录无需重新发起模型问答；若主动发送普通问题，原有模型调用与费用仍会发生。本轮没有重新评估远端回答准确率、来源支持率、召回率、时延或费用，不改写[第四周结果](week4-report.md)及其失败记录。

本机固定身份、明文业务存储、有限凭证拦截、Streamlit DOM 选择器兼容性等边界继续存在。产品外观开关不是生产安全模式；新设置既不提供登录/权限控制，也不允许模型绕过按钮确认。这里只保留显示配置，不增加多 Agent、远端设置服务、附件处理或企业部署能力。
